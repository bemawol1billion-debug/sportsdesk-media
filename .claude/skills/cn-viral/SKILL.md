# cn-viral

조사 스킬. 다른 cn- 스킬은 쓰고, 이건 보러 간다. 주 1회(월요일 `/cn-plan` 전)와 막혔을 때.

## 핵심 하나

**남의 큰 숫자는 근거가 아니다.** 팔로워 200만 계정의 좋아요 2만은 평범한 날이고, 팔로워 1만
계정의 좋아요 2만은 뭔가를 찾은 것이다. 그래서 **아웃라이어 배수**(이 게시물 좋아요 ÷ 그 계정 최근
12개 좋아요 중간값)로 줄 세운다. 3배 이상이면 신호, 1.5배 미만이면 평범한 날.
카드 게시물은 조회수가 안 보이니 좋아요(+댓글)를 쓴다.

우리 계정 크기의 약 10배 안쪽 계정이 가장 쓸모 있다.

## 1. 계정 고르기 (6~12개, 사용자 승인)

- **4곳 직접:** 스포츠 뉴스·카드뉴스 계정, 조금 앞선 곳.
- **4곳 옆 분야:** 경제·생활정보·시사 카드뉴스. 형식을 먼저 빌려 오는 곳.
- **2~4곳 큰 계정:** 형식만 참고. 빈도·말투는 따라 하지 않는다.

사용자의 "저장됨" 모음도 열어 달라고 한다. 이미 취향으로 걸러진 가장 빠른 자료다.

## 2. 보러 가기

이 세션에 있는 브라우저 도구를 쓴다(내장 브라우저, 사용자 Chrome).

**지킬 것:**
- **사용자 대신 인스타에 로그인하거나 비밀번호를 묻지 않는다.** 로그인이 필요하면 사용자가 이미
  로그인한 브라우저를 함께 보거나 붙여 넣기를 부탁한다.
- **읽기만 한다.** 계정 10개, 게시물 십수 개씩, 사람 속도. 수집 프로그램·수집 서비스·백그라운드
  반복 금지. 대량 수집은 인스타 약관 위반이고 계정이 제한된다.
- **공식만 가져온다.** 표지 모양, 구성, 장수, 요청 방식. 남의 문장·이미지·디자인은 가져오지 않는다.
  출처 계정을 모든 줄에 적는다.

**게시물마다 적을 것:**

| 항목 | 설명 |
|---|---|
| 계정 | 핸들 |
| 팔로워 | 프로필에서 |
| 중간값 | 최근 12개 게시물 좋아요의 가운데 값 |
| 좋아요·댓글 | 이 게시물 |
| 표지 문구 | 그대로(틀린 맞춤법도) |
| 장수 | |
| 요청 | 마지막 장·캡션에서 무엇을 요청했나 |
| 형식 | 카드 / 단일 이미지 |

중간값이 가장 중요하다. 없으면 다시 팔로워 순으로 줄 세우게 된다.

## 3. 줄 세우고 분류

아웃라이어 배수를 계산하고, 표지마다 `/cn-carousel`의 공식 번호(C1~C10)를 붙인다. 어디에도 안
맞는 표지는 "분류 못 함"으로 따로 둔다.

## 4. 조심해서 말하기

딱 세 가지만 보고한다.

1. **상위 1/3에 몰린 공식**(개수와 함께). 계정 6곳에서 네 번씩 나온 공식 두 개는 발견이고, 두 번
   나온 하나는 아니다.
2. **상위와 하위의 구조 차이:** 표지 글자 수, 숫자 유무, 사진/글씨판, 장수, 요청 위치.
3. **분류 못 한 표지.** 잡음이거나 아직 목록에 없는 새 공식이다. 손으로 읽는다. 가장 값진 칸이다.

표본 수와 확신 정도를 말로 적는다. 게시물 40개는 주장할 수 있고, 12개는 못 한다.

## 5. 우리 표지로

상위 공식 3개를 **우리 버전 표지 한 줄**로 바꾼다. 이번 주 실제 소식과 숫자로. "이 게시물처럼"이
아니라 내일 쓸 수 있는 표지로. 새 공식을 찾았으면 `/cn-carousel` 표에 추가를 제안한다.

## 출력

```
참고 자료 · 게시물 38개 · 계정 7곳 · 기준: 계정별 중간값

아웃라이어(3배 이상)
  9.2x  C1 숫자충격  @acct_a  좋아요 4,100 (중간값 445)  "연봉 0원, 그런데 MVP"
  ...
몰린 공식
  C1 x5 상위, 하위 0 / C5 x3
분류 못 함(4): 두 개가 '팬 댓글을 표지로 쓰기' 모양. 새 공식 후보.
우리 버전
  C1 "11경기 10승, 이게 말이 돼?"
```

저장소 `content/swipe.md`에 쓴다. `/cn-plan`과 `/cn-carousel`이 읽는다. 이 스킬은 아무것도
게시·팔로우·좋아요·메시지하지 않는다. 읽기만 한다.
