## 1. 꼭 지킬 규칙

1. 대화·원고·캡션은 모두 **한국어**로 쓴다.
2. **"제작"(`wpwkr` 포함) 승인 전에는 게시·예약하지 않는다.** "제작으로 가보자"처럼 진행을 뜻하는 말도 승인으로 본다.
3. ⭐ **완성본 확인 후 게시:** 이미지까지 넣어 렌더한 완성 카드(미리보기 시트 + 장별 PNG)를 보내고, 확인을 받은 뒤에만 예약·게시한다. 수정해서 다시 렌더했을 때도 다시 확인받는다. 확인 없이 슬롯 시각이 지나면 게시하지 않고 다음 슬롯을 제안한다.
4. **항상 폰으로 보낸다:** 파일은 폰에서 받을 수 있게 보내고, 승인 요청·설문형 자료 전달·예약 완료·오류 때는 알림도 보낸다. (모바일 푸시는 사용자가 Claude Code `/config`에서 켜야 함. 11/8 기준 꺼져 있음)
5. **표지 후킹 우선:** 🆕
   - 첫 장 큰 제목은 다음 장으로 넘기게 만드는 게 목적이다. **과장·단정 표현을 주로 쓴다.**
   - **타이틀은 주제에 맞게 자극적으로 만든다.** 사용자가 타이틀을 제시하면 맞춤법만 고쳐서 그대로 쓴다.
   - 2장부터의 본문과 캡션 본문은 **사실만** 쓴다. 표지가 앞서 나가면 본문에서 실제 단계를 밝힌다.
   - 없는 사건·숫자를 지어내지 않는다. 실존 인물이 하지 않은 말을 따옴표로 붙이지 않는다. 팀·선수·팬을 비하하지 않는다.
6. **사실 확인:**
   - 사실 하나마다 보도 2곳 이상으로 확인한다. 1곳뿐인 숫자는 승인 요청 때 따로 표시한다.
   - 쓰기 직전과 예약 직전에 최신 상황을 다시 검색한다.
   - 기사 문장은 옮기지 않고 새로 쓴다. 직접 인용은 15단어 미만으로 1회까지만.
   - 각 장 하단에 출처 언론사명을 단다.
7. 🆕 설문 금지 주제는 없앴다(11/8). 단, 5번의 기본선(지어내기·가짜 인용·비하 금지)은 설문형에도 그대로 적용한다.

## 2. 이미지 ⭐ (11/8 개편)

**기본은 실사 이미지다.** 글씨판은 이미지를 구할 수 없을 때만 쓴다.

| 순위 | 이미지 | 기준 |
|---|---|---|
| 1 | **사용자가 보내 준 이슈 사진** | 이슈가 된 실제 사진(보도·선수 사진 포함)은 사용자가 직접 올려 주면 최우선으로 쓴다. 이런 사진은 Claude가 직접 찾아 가져오지 않는다. 필요하면 승인 요청 때 "이 사진 있으면 보내주세요"라고 요청한다. |
| 2 | **무료 사진 사이트의 실사 사진** | Unsplash·Pexels 등 무료로 상업 이용할 수 있는 사진만 쓴다. 그 종목을 하는 실제 사람 사진도 되고, 경기장·공·장비·관중석 사진도 된다. 보도 사진과 유명 선수가 알아보이는 사진은 쓰지 않는다. 라이선스를 사진 페이지에서 확인한다(Unsplash+ 유료 사진 제외). |
| 3 | **Canva AI 실사 선수** | Canva `generate-image`로 그 종목 선수를 실사처럼 만든다. 실존 선수와 닮지 않게, 로고·글자 없이. 애니메이션·만화 느낌은 금지. **Higgsfield 금지.** |

- **출처 표기:**
  - 표지 `photo.credit`에 "사진: 작가 / Unsplash" 형식으로 적는다. 숫자 배지와 겹치면 작가 이름을 줄인다.
  - 캡션 출처 줄 아래에 "표지 사진: 작가 / Unsplash (자료 사진)"을 넣는다.
  - AI 이미지면 "AI 생성 이미지"로 적고, 인스타 AI 라벨을 켜 달라고 안내한다.
- **원본 보관:** 사진 원본은 `스포츠데스크\cardnews_photos\YYYY-MM-DD\`에 둔다. 공개 저장소에는 커밋하지 않고, 완성 카드 PNG만 `cards/`에 올린다.
- **원고 기록:** 원고 JSON의 `image`에 출처(사이트, 사진 ID, 링크, 작가, 라이선스)를 남긴다.
- ⭐ **표지 화살표 없음:** 렌더러에서 표지 낙서 화살표를 뺐다(11/8). 하단 "옆으로 넘겨서 보기 →" 문구는 유지한다.

## 3. 형식과 주제

### 하루 구성
- 하루 3개: **일반형 2 + 설문형 1**.
- 이슈 1개 = 게시물 1개, 3~5장, 1080×1440 PNG.
- 같은 날 3개는 종목이 겹치지 않게 한다.

### 주제 방향 (가장 중요)
- **지난 게시물의 후속·연장선은 내지 않는다.** 같은 시리즈의 다음 경기나 같은 팀 기록 업데이트도 마찬가지다. 매일 새 화제를 낸다.
- 우선 찾는 주제:
  1. 이슈가 된 문제(논란·화제)
  2. 뉴스로 나온 새 소식
  3. 다가오는 정책·일정
  4. 새로 생기거나 없어지는 제도·규정·시설
  5. 🆕 일반인이 참여할 수 있는 대회·이벤트, 또는 빅 스포츠 이벤트(올림픽·월드컵·아시안게임·WBC 같은 대형 대회와 그 일정·예매·응원 정보)
- 경기 결과·선수 기록만으로 된 게시물은 줄인다. 승인 요청 표에 이슈마다 1~5 중 어디인지 적는다.
- 같은 갈래(지원·혜택형, 선두 팀 기록형 등)나 같은 카드 구성(text→stats→why)을 이틀 연속 쓰지 않는다. compare(비교표)·dday(일정표)·찬반표를 섞는다.
- 실패 사례: 11/8 첫 시안 3개(헬스장 소득공제·수원 삼성 승격·KS 5차전 설문)는 "앞전 게시물과 비슷하다"는 이유로 전부 교체됐다.

### 생활정보형
- 하루 1개 이상, 보통 일반형 1개.
- 범위: 지원금·바우처, 세금, 리그 제도·규정, 시설, 새 서비스·예매, 시즌 정보(스키장·마라톤), 🆕 **일반인 참여 대회·이벤트**(마라톤·생활체육 대회·구단 팬 이벤트·체험 행사 등, 신청 기간·참가비·장소 포함).
- `sport_en: "SPORTS INFO"`를 쓴다.
- 신청 기간·금액은 공식 발표나 보도 2곳으로 확인한다. 지역마다 다르면 "지자체 공고 확인"을 넣는다.

### 설문형
- 의견이 정반대로 갈리는 대결 구도로 만든다. 승부, 타이틀, 판정 논란, 기록 전망, 제도 찬반, "동의하나요?" 같은 유형이다.
- vote 카드와 캡션의 질문은 직접 묻는다. "누가 웃을까?" 같은 돌려 말하기는 금지다.
- 선택지 2개는 각 15자 이내로, 서로 정반대여야 한다.
- 근거는 양쪽 2줄씩 공평하게 쓰고 우리 의견은 넣지 않는다.
- 표지에 `vote_chip: "투표 진행중"`을 단다. 후킹 타이틀을 쓰면 직접 질문을 부제로 내린다.
- 마지막 장은 `vote` 카드다. 결과 공개는 약속하지 않고, "3일 후 설문 종료"는 끈다.
- 캡션 첫 줄은 🗳 + 후킹·질문이고, 끝은 "아래 설문에 투표하고, 그렇게 생각한 이유를 댓글로 남겨주세요 👇"다.
- 인스타 설문은 API로 붙일 수 없어서 **사용자가 앱에서 수동 업로드**한다.

### 일반형
- 설문·투표·"댓글로 A/B" 요청은 넣지 않는다.
- 마무리 장에 저장·팔로우·친구 태그·응원 댓글 CTA를 넣는다.
- 캡션 구성: 첫 줄 후킹 + 사실 3~4문장 + CTA + 출처(+ 사진 출처 / AI 표기) + 해시태그 5개.

## 5. 게시 절차

### 일반형 (Zernio 자동 예약)
1. `cards/YYYY-MM-DD/<원고파일명>/01~05.png`을 커밋하고 push한다. 커밋 메시지 끝에 Co-Authored-By 줄을 넣는다.
2. 1~2분 뒤 Pages 주소를 `validate_media`로 확인한다. `valid: true`이고 크기가 로컬 파일과 같아야 한다.
3. ⭐ 완성본 확인을 받은 뒤 `posts_create`를 실행한다.
   - `platform: instagram`, `account_id: 6ae7ecfd107612384b344718`
   - `media_urls`: 쉼표로 이어서 순서대로
   - `content`: 캡션 전문
   - `schedule_minutes`: 현재 KST에서 슬롯까지 남은 분
   - 결과 시각은 UTC로 표시된다(21:00 KST = 12:00 UTC).
4. `posts_list status=scheduled`로 확인하고 post ID를 보고한다.
- 이미 push한 이미지를 고칠 때는 **새 폴더·파일명**을 쓴다(Pages 캐시 때문). 예약을 바꿀 때는 기존 예약을 지우고 새로 만든다.
- `raw.githubusercontent.com` 주소는 쓰지 않는다. Pages 주소만 쓴다.

### 설문형 (사용자 수동)
1. PNG를 `설문형_<키워드>_01~05.png`로 한 장씩 첨부해서 보낸다.
2. 메시지로 다음을 보낸다.
   - ① 캡션(복사용 코드 블록)
   - ② 선택지 2개
   - ③ "3일 후 설문 종료 끄기"
   - ④ 권장 업로드 시각
   - ⑤ AI 이미지면 AI 라벨 켜기
3. 완성 카드는 `cards/`에도 push한다.
4. "올렸어"라고 하면 log.md의 해당 줄을 업로드 완료로 고친다.

### 기록
- `content/log.md`에 한 줄씩 적는다.
  - 항목: 날짜, 게시물, 일반형/설문형, 게시 시각, post ID, 비고
  - 비고에는 이미지 종류(사용자 사진 / 무료 사진 / AI / 글씨판)와 사진 출처를 적는다.

## 7. 🆕 인사이트 확인과 적용 (11/8 추가)

게시 뒤 성과를 확인하고, 잘된(터진) 게시물의 원인을 다음 게시물에 적용한다.

1. **언제:** 매일 05:51 작업 시작 때 지난 게시물을 확인한다. 게시 24시간 뒤와 72시간 뒤 수치를 기준으로 본다. 매주 월요일에는 지난 7일을 묶어 주간 정리를 한다.
2. **무엇을:** Zernio `analytics_get_analytics` / `analytics_get_post_timeline`으로 게시물별 도달·노출·좋아요·댓글·저장·공유를 가져온다. 설문형은 수동 업로드라 Zernio에 없을 수 있으니, 사용자에게 인사이트 화면 캡처를 요청한다.
3. **터진 게시물 판단:** 최근 14일 게시물의 중간값보다 도달이 2배 이상이거나, 저장·공유가 상위 20%이면 "터진 게시물"로 본다(4주 운영 뒤 기준을 조정한다).
4. **원인 분석:** 터진 게시물과 부진한 게시물을 아래 항목으로 비교한다.
   - 주제 유형(1~5)
   - 종목
   - 표지 타이틀 형태(과장·단정·질문·숫자)
   - 이미지 종류(사용자 사진·무료 실사·AI·글씨판)
   - 카드 구성
   - 게시 시각
   - 일반형/설문형, 설문 질문 유형
5. **적용:** 분석 결과를 `content/insights.md`에 날짜별로 적는다(게시물, 수치, 원인 추정, 다음에 적용할 점). 다음 날 주제 선정과 타이틀·이미지·구성에 반영하고, 승인 요청 메시지에 "어제 분석에서 적용한 점" 한 줄을 넣는다.
6. **주의:** 터진 게시물의 주제를 그대로 이어 가지는 않는다(후속편 금지 규칙은 그대로). 형식·타이틀 방식·이미지 같은 "만드는 방법"을 가져온다.
